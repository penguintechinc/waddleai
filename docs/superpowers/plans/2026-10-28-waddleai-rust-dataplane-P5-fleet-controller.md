# WaddleAI Rust Data-Plane — P5 Fleet Controller Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace imperative, API-triggered fleet management with a `kube-rs` reconcile controller over desired-state CRDs. The Management API becomes the CRD *writer* (RBAC scopes unchanged); the controller reconciles CRDs into DaemonSets, Services and Cilium objects, performs model pulls, enforces node/VRAM caps, and lands the idle-teardown scheduler. The Python managers retire at parity.

**Architecture:** New crate `waddleai-fleet-controller` (bin) + `waddleai-fleet-api` (lib: CRD types, shared with `xtask` CRD generation) + `waddleai-fleet-backends` (lib: the Rust `InferenceFleetBackend` traits and reqwest cloud clients) in the P0 `rust/` workspace. One generic reconcile skeleton (`Reconciler` trait, §Interfaces) is instantiated per CRD kind; side-effects go through narrow ports (`KubeOps`, `OllamaApi`, `Clock`, `CapPolicy`) so reconcile logic is unit-testable with fakes (`tower-test` mock `kube::Client`, in-memory port fakes) and only a thin envtest/kind tier touches a real apiserver.

**Tech Stack:** Rust (P0 pinned toolchain), `kube` (+`kube-runtime`, `kube-derive`) and `k8s-openapi` pinned to exact, mutually compatible versions (feature `v1_3x` matched to the dal2/dal3 cluster minor), `schemars`, `tokio`, `reqwest`, `serde`, `tracing` + P0 telemetry, `tower-test`, `wiremock`, `cargo-llvm-cov`, `cargo-deny`. Reuses P0 `Config`, `db` (read-only SeaORM entities), telemetry, `/healthz /readyz /metrics`.

**Spec:** `docs/superpowers/specs/2026-10-28-waddleai-rust-dataplane-migration-design.md` §5.4 (fleet controller) and §10.4 (owner decision: Management API writes CRDs -> Rust controller reconciles -> Python managers retire at parity). **Depends only on P0**; parallelizable with P2.

## Global Constraints

- **kube-rs + k8s-openapi pinned** to exact versions in `Cargo.toml`/`Cargo.lock`; `k8s-openapi` Kubernetes-version feature must match the target clusters. `cargo-deny` enforces pins, licenses, and no PRC/sanctioned crates.
- **Rust never owns DB migrations.** The controller reads fleet rows only through P0's generated SeaORM entities (e.g. `fleet_backends`, `ollama_deployments`, `llamacpp_deployments`) and never writes DDL. Where it must persist status it writes the CRD `.status` subresource, not new tables. Any new column a task needs is a separate Alembic migration owned by Python.
- **CRDs are installed via Helm** (`k8s/helm/waddleai/crds/` generated by `cargo xtask gen-crds`; CI drift check fails if generated YAML differs from committed). The controller never creates/updates CRDs at runtime.
- **Security baseline:** controller runs rootless (`runAsNonRoot`, read-only rootfs), stateless (all state in CRDs/Postgres), minimal ClusterRole (no wildcards, extends `cilium-rbac.yaml` pattern). Fleet pods themselves keep Cilium default-deny + egress allowlist, Tetragon `TracingPolicy` allowlist for `ollama`/`llama-server` binaries, and PSA `restricted` (GPU DaemonSets that need device access carry an explicit documented exception, same as today's templates).
- **RBAC scopes retained:** `FLEET_ADMIN` (`fleet:admin`), `CILIUM_ADMIN` (`cilium:admin`), `LLAMACPP_ADMIN` (`llamacpp:admin`), `OLLAMA_ADMIN` (`ollama:admin`) authorize the Management API's CRD writes. The controller trusts only the CRD; authorization happens at the writer. The Management API's own K8s ServiceAccount gets create/update/delete on `waddleai.penguintech.io` CRDs only (no DaemonSet/Service/Cilium write access any more).
- **Feature-flagged, default OFF:** PostHog flag `waddleai.fleet-controller` gates the Management API CRD-write path (OFF = legacy Python managers). Core-mechanism kill-switch semantics per `critical-rules.md`. The controller reconciles only CRs carrying `waddleai.penguintech.io/managed-by: controller` so Python and Rust never fight over the same object.
- **Idempotent, level-triggered, server-side apply** (`PatchParams::apply("waddleai-fleet-controller")`, `force` only on owned fields); owner references + finalizers for cleanup; no read-modify-write races.
- **Shared multi-tenant:** CRs live in the `waddleai` namespace (cluster-wide namespace is the product name); org scoping is an `orgPublicId` UUID label/field, never numeric PK or name (`critical-rules.md` Entity Identity). No per-tenant stacks.
- **Telemetry:** every reconcile emits a span, `waddleai_fleet_reconcile_total{kind,result}`, `waddleai_fleet_reconcile_duration_seconds` histogram, queue-depth gauge; penguin/`tracing` logging, OTLP from `OTEL_*`; a dead exporter never fails a reconcile.
- **Coverage:** `cargo-llvm-cov` >= 90% (lines/branches/functions), CI-enforced; reconcile logic is pure over ports so the bar is reachable without a cluster.
- **Fail loud:** unimplemented backend operations return a typed `FleetError::Unsupported`, never silently succeed (no-stubs gate).

## Review Focus

- **Reconcile drift / idempotency:** running reconcile N times against unchanged state produces zero writes after the first; out-of-band edits to a managed DaemonSet are reverted; no hot-loop requeue -> Tasks 3, 5, 6.
- **DaemonSet reattach:** controller restart / CR delete+recreate must adopt the existing DaemonSet and PVC (same name, owner-ref re-stamped), never recreate or orphan model storage -> Task 5.
- **Cilium CRD apply failure -> degrade, not crash:** missing Cilium CRDs, webhook rejection, or RBAC denial sets `Degraded` condition + backoff requeue; the DaemonSet/Service reconcile for the same fleet still proceeds; controller never panics or exits -> Task 7.
- **Model-pull failure:** pull timeout, disk-full, registry 5xx, partial pull; must be retried with capped backoff, surfaced in `.status.models[]`, never block unrelated models or mark a half-pulled model `Ready`; placement must not route to it -> Task 8.
- **CRD version skew:** controller older/newer than installed CRD; unknown fields; Python writer vs Rust reader schema agreement; storage-version migration path (v1alpha1 -> v1beta1 via conversion) -> Tasks 2, 11.
- Also: cap enforcement races between two CRs applied concurrently (Task 6), idle teardown deleting a node that just received traffic (Task 9), cloud-client secrets never logged (Task 10).

### Reconcile trait (one generic skeleton, per-kind impls)

```rust
/// Pure reconcile contract: desired CR + observed world -> idempotent actions.
#[async_trait]
pub trait Reconciler: Send + Sync + 'static {
    type Resource: kube::Resource + Clone + serde::de::DeserializeOwned + Send + Sync;
    type Ctx: Send + Sync;
    /// Make the world match `obj.spec`; return when to look again.
    async fn reconcile(&self, obj: Arc<Self::Resource>, ctx: Arc<Self::Ctx>)
        -> Result<ReconcileOutcome, FleetError>;
    /// Finalizer path: delete owned children, never the PVC unless `purge`.
    async fn cleanup(&self, obj: Arc<Self::Resource>, ctx: Arc<Self::Ctx>)
        -> Result<ReconcileOutcome, FleetError>;
    /// Error -> requeue policy (backoff, jitter; terminal vs transient).
    fn error_policy(&self, obj: Arc<Self::Resource>, err: &FleetError, ctx: Arc<Self::Ctx>)
        -> kube::runtime::controller::Action;
}
pub struct ReconcileOutcome { pub requeue_after: Option<Duration>, pub status: StatusPatch }
pub enum FleetError { Transient(anyhow::Error), Terminal(String), CapExceeded{..}, Unsupported(&'static str), CrdSkew{..} }
```

### `InferenceFleetBackend` as Rust traits (re-expression of `shared/fleet/base.py:104`)

```rust
pub enum BackendType { Ollama, LlamaCpp, Exo, VertexAi, Bedrock, AzureAi, OllamaCloud, HuggingFace }
pub enum ManagementScope { RegisterAndRoute, FullLifecycle }
pub struct Endpoint { pub url: Url, pub node_id: String, pub loaded_models: Vec<String>, pub healthy: bool }
pub struct NodeInfo { pub node_id: String, pub node_uid: Option<String>, pub kind: NodeKind,
                      pub loaded_models: Vec<String>, pub vram_total_mb: u64, pub vram_free_mb: u64, pub healthy: bool }
pub struct ModelPlacement { pub model: String, pub node_id: String, pub status: PlacementStatus } // Placed|Pulling|Denied
pub struct ProvisionSpec { pub name: String, pub models: Vec<String>, pub mode: String, pub constraints: Constraints }
pub struct FleetHealth { pub backend_id: i64, pub healthy: bool, pub node_count: u32, pub detail: serde_json::Value }

/// Read/route surface — implemented by EVERY backend (cloud + k8s).
#[async_trait] pub trait FleetRouting: Send + Sync {
    fn backend_type(&self) -> BackendType;
    fn management_scope(&self) -> ManagementScope;
    async fn health(&self) -> Result<FleetHealth, FleetError>;
    async fn list_nodes(&self) -> Result<Vec<NodeInfo>, FleetError>;
    async fn place_model(&self, model: &str, c: &Constraints) -> Result<ModelPlacement, FleetError>;
    async fn endpoints_for(&self, model: &str) -> Result<Vec<Endpoint>, FleetError>;
}
/// Lifecycle surface — FullLifecycle backends only; RegisterAndRoute impls return Unsupported.
#[async_trait] pub trait FleetLifecycle: FleetRouting {
    async fn provision(&self, spec: &ProvisionSpec) -> Result<Vec<NodeInfo>, FleetError>;
    async fn deprovision(&self, node_id: &str) -> Result<(), FleetError>;
}
```
The six Python methods map 1:1 (`provision`/`deprovision` -> `FleetLifecycle`; `health`/`list_nodes`/`place_model`/`endpoints_for` -> `FleetRouting`). In the controller, `FleetLifecycle::provision/deprovision` are implemented as "write/patch the `InferenceFleet` CR + await `Ready`" so the proxy's placement path (P3) and the Management API both speak CRDs, never raw K8s.

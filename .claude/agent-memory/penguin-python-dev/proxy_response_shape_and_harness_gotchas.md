Wave-2 audit (audit-2026-09-14-wave2) hardening of `proxy/apps/proxy_server/main.py` + `mem0_api.py`.

**The proxy's malformed-body 500 was a documented bug pinned in FOUR places** — same "tests encode broken behaviour" trap as [[tests-encode-broken-behaviour]]. `/v1/chat/completions` and `/v1/messages` read `await request.get_json()` (no `silent=`); a non-JSON body raised Quart `BadRequest`, caught by the handler's broad `except Exception` → generic 500. This 500 was locked by: golden snapshots `tests/contract/snapshots/proxy_chat_completions_malformed.json` + `proxy_messages_malformed.json`, AND unit tests `test_malformed_body_returns_500` in `TestChatCompletions`/`TestClaudeMessages` (`tests/unit/proxy/test_proxy_server_main.py`) — all with docstrings explicitly saying "currently 500s, not 400s ... intentional: lock in *current* behavior." Fix: `get_json(silent=True)` + a validate helper that returns a 400 in the format-correct envelope (OpenAI `{"error":{"message","type":"invalid_request_error"}}`, Anthropic `{"error":{"type":"invalid_request_error","message"}}`). Had to flip all 4 to expect 400 and regenerate the 2 snapshots. **Regenerate contract snapshots deterministically without booting the server**: import `tests/contract/snapshot.py::_normalize`, build `{"status":..,"body":_normalize(body)}`, `json.dumps(indent=2, sort_keys=True)+"\n"` — byte-identical to what `assert_snapshot` writes under `CONTRACT_RECORD=1`. Normalizer sorts keys, so OpenAI vs Anthropic error key-order differences collapse to the same file.

**Kept `model` optional on both endpoints** — chat falls back to `"gpt-3.5-turbo"`, messages to `"claude-3-sonnet-20240229"`. Only `messages` (non-empty list of objects) is strictly required; validating `model` type-only preserves the intentional default-model feature and the accepted-request contract. Every e2e/contract/unit accepted request sends both model + non-empty messages, so requiring messages is safe.

**`mem0_api.py` was ALREADY hardened — no code change needed.** Its search/list handlers build EXPLICIT per-item dicts `{id, memory, user_id, score, metadata, created_at, scope, author_user_id}` from `entry.*` attrs (not `**__dict__`), deliberately omitting `embedding` and `organization_id`. add/delete/clear likewise hand-build fixed dicts. Only deliverable was regression tests pinning the exact per-item key set (the `_entry()` fixture sets `embedding`/`organization_id`, so a leak would be caught). Tenant/org derivation is token-authoritative — do not weaken.

**Output-shape raw pass-throughs that DID need fixing** (main.py): `/api/usage` (`jsonify(stats)`), `/api/memory/stats` (`jsonify(stats)`), `/api/quota` (`jsonify({"quota_ok":.., **quota_info})` — the splat). Reproject each onto an explicit allowlist helper at the handler boundary. `/api/routing/stats`, `/api/status`, `/v1/models`, count_tokens were already explicit hand-built dicts (left as-is; `/v1/models` items come from connector `list_models()` and are OpenAI-wire-sensitive — left conservative).

**Contract/e2e subprocess harness is unrunnable in this shared sandbox.** `tests/contract/conftest.py::_wait` hard-codes a 30s readiness timeout; `_launch` boots the proxy via `sys.executable -m hypercorn`. Manual boot is ~2-3s, but with ~14 sibling hypercorn processes from parallel agents contending for CPU, the pytest-launched subprocess never passes `/healthz` inside 30s → every contract/e2e proxy test ERRORs "never became ready". Verify via the in-process `running_app` unit fixture instead (no subprocess) + deterministic snapshot regen. Also: `pkill -f "hypercorn apps.proxy_server"` would kill SIBLING worktree agents' proxies — never broad-pkill in this sandbox.

**Verification that worked here:** `tests/unit/proxy/` full = 569 passed (in-process). ruff clean. mypy-gate = `examined 453 source files, 0 new` (empty baseline; run `PY=.venv/bin/python bash scripts/mypy-gate.sh` from the worktree root — its `exclude` has `^\.worktrees/` which does NOT match when cwd IS the worktree, so it checks normally).

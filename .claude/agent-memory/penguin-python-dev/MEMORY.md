- [E2E suite + penguin_dal gotchas](e2e_suite_and_penguin_dal_gotchas.md) — `tests/e2e/` real pytest suite (subprocess proxy, real HTTP); systemic `.update_record()` is not a penguin_dal API (fixed in rbac.py/token_manager.py, broke ALL api-key auth + usage accounting; still broken in 3 management files); `_load_custom_rules` PyDAL-chaining bug fixed; `get_db()` reflect=True collision on 2nd call (worked around, not fixed); `cache_configs` is Alembic-only, unreachable under sqlite stub-upstream harness; Makefile `-d`-guard vacuous-pass fix on 4 targets; use `/usr/bin/python3` not PATH's in this sandbox.
- [WaddleAI management test harness gotchas](waddleai_management_test_harness_gotchas.md) — `tests/unit/__init__.py` missing causes dual-module conftest import (`make_token()` signed with wrong OIDC keypair if imported directly instead of via fixture); `WaddleAIMetrics` per-instance Counter/Histogram construction collided across `get_proxy_metrics()`/`get_management_metrics()` singletons (fixed: Borg-style shared collectors).
- [Smoke test fix + orjson gap](smoke_test_fix_and_orjson_gap.md) — `make smoke-test` rewired to run `tests/smoke/test_management_build.sh` directly (0-collected pytest fixed); script itself had a `set -e`+`((x++))` bug that killed it after 1 line, ever; found missing `orjson` dep breaks container boot (not fixed, out of scope).
- [mem0ai envelope response shape](mem0ai_envelope_response_shape.md) — mem0ai 2.0.18 `MemoryClient.search()`/`.get_all()` return `{"results": [...]}` envelope not a bare list; no `py.typed` so mypy can't catch it; fixed via `_normalize_mem0_results()` in `memory_integration.py`.
- [Management route gates & test traps](management_route_gates_and_test_traps.md) — existing tests can encode a vuln as expected behaviour (`test_set_key_quota_regular_user_own_key` asserted 200 for self-escalation); `mypy-baseline.txt` is EMPTY so any new type error fails (and annotating an untyped route starts body-checking `db: DB | None` — use `_db()`); `openapi/v1.yaml` is CI drift-gated + a parallel-agent conflict magnet; pytest-cov/ruff/bandit absent from requirements.txt so a fresh venv can't run pytest at all.
- [SQL-only tenant filters are untestable here](management_authz_testability_and_openapi_gate.md) — the management mocked DB ignores the query, so isolation tests pass with the fix reverted unless a Python-side row guard exists; plus the fresh-venv recipe and full-suite denominators.
- [penguin-aaa token TTL + jti](penguin_aaa_token_ttl_and_jti.md) — `issue_token_set()` ignores `claims.exp` and uses `config.token_ttl` (real TTL was 1h, not the audited 24h); `max_token_ttl` defaults to 1h and RAISES at construction so `TOKEN_TTL_HOURS=2` crashed startup; `jti` already stamped on every token; reuse `RedisTokenStore.add_revoked_jti`, but type against a local 2-method Protocol or mypy fails.
- [Management venv + requirements](management_venv_and_requirements.md) — use `services/management/requirements.txt` not the root one (root omits `quart-cors`, failing as a misleading `AttributeError: module 'services.management' has no attribute 'app'`); `pytest-cov` is in no requirements file but `pytest.ini` addopts demand it; `--cov=` needs the slash path or it collects zero and reads as a pass.
